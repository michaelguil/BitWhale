# Bitcoin 고래 트랜잭션 분석: 정보 비대칭성 문제 해결을 위한 데이터 기반 접근

## 1. 도전 과제 및 주요 목표

### 1.1. 도전 과제
변동성이 매우 큰 암호화폐 시장에서, 개인 투자자는 '고래'라 불리는 거대 투자자들의 움직임에 큰 영향을 받지만 관련 데이터를 쉽게 얻거나 해석하기 어려워 정보 비대칭성으로 인한 리스크에 항상 노출되어 있습니다. 이 프로젝트는 주식 시장의 '거대 투자자 추종' 전략을 비트코인 생태계에 적용하여, 데이터 기반의 분석을 통해 이 문제를 해결하고자 시작되었습니다.

### 1.2. 주요 목표
- 고래 투자자 특정: 트랜잭션 데이터를 기반으로 '고래'로 분류될 수 있는 지갑들을 특정하고 분류합니다.
- 매매 동향 제공: 특정된 고래들의 움직임을 실시간으로 추적하여 매매 동향 정보를 제공합니다.
- 모델 유효성 검증: 고래 매매 동향을 이용한 모의 투자를 통해 분석 모델의 유효성을 검증합니다.

## 2. 핵심 문제 해결 과정: "고래"의 기준을 정의하다

프로젝트 초반, 저희 팀은 "고래를 어떻게 정의할 것인가?"라는 근본적인 문제에 직면했습니다. '고래'라는 용어는 널리 쓰이지만, 정량화된 업계 표준이 없어 분석의 첫 단계를 진행할 수 없는 상황이었습니다.

이를 해결하기 위해, 저희는 가설을 세우고 데이터를 통해 검증하는 접근 방식을 사용했습니다.

1.  문제 정의: '고래'를 식별하기 위한 명확하고 정량적인 기준이 필요했습니다.
2.  탐색 및 분석: 관련 논문, 금융 기사, 그리고 실제 블록체인 트랜잭션 데이터를 분석하여 고래의 행동 패턴(거래 규모, 빈도, 보유 기간 등)에 대한 인사이트를 수집했습니다.
3.  솔루션(모델 정립): 수집한 인사이트를 바탕으로, '포지션', '거래 규모', '거래 빈도'라는 세 가지 축을 기준으로 고래를 분류하는 자체적인 '분석 모델'을 정립했습니다. 이 과정은 불분명한 문제를 구체적인 분석 기준으로 정의하는 핵심적인 문제 해결 과정이었습니다.

이 경험을 통해 명확한 기준이 없는 복잡한 문제를 데이터 분석과 논리적 추론을 통해 구조화하고 해결하는 역량을 기를 수 있었습니다.

## 3. 분석 모델 (Analysis Model)

위의 문제 해결 과정을 통해 저희가 직접 정의한 '고래' 분류 기준은 다음과 같습니다.

| 구분 | 정의 / 규모 (X = BTC) / 평균 보유 기간 (μΔ) |
| :--- | :--- |
| 포지션 (Position) | Long (진입가 < 청산가) / Short (진입가 > 청산가) |
| 거래 규모 (Trade Size) | Small (10 ≤ X < 100) / Medium (100 ≤ X < 500) / Large (500 ≤ X) |
| 거래 빈도 (Trading Frequency)| Scalper (μΔ ≤ 1일) / Short Swing (1 < μΔ ≤ 14일) / Long Swing (14 < μΔ ≤ 30일) / Long Term (30일 < μΔ) |

## 4. 기술 스택 및 핵심 아키텍처

| 구분 | 기술 / 아키텍처 | 설명 |
| :--- | :--- | :--- |
| 핵심 언어 | Python | 데이터 처리, 분석 및 워크플로우 자동화를 위한 주력 언어로 사용했습니다. |
| 데이터 처리| Pandas | 원본 TSV/CSV 파일로부터 트랜잭션 데이터를 효율적으로 필터링, 변환, 분석하는 데 사용했습니다. |
| 블록체인 연동| Bitcoin Core (JSON-RPC) | `python-bitcoinrpc` 라이브러리를 통해 Bitcoin 노드와 직접 통신하며, 이는 API 연동 역량을 보여줍니다. |
| 핵심 아키텍처| 모듈화 설계 | 기능별로 코드를 모듈화하여 유지보수성을 향상시켰습니다. |
| | 테스트 용이성을 위한 시뮬레이션 모드| Bitcoin 노드 없이도 핵심 로직을 테스트할 수 있도록 구현하여, 엔지니어링 마인드셋을 보여줍니다. |

## 5. 데이터 파이프라인 및 워크플로우 자동화

```
1. 데이터 수집 (Data Ingestion)
   - `data/` 디렉토리에 원본 트랜잭션 데이터(.tsv)를 준비합니다.
     ↓
2. 전처리 및 필터링 (src/main.py)
   - Python 스크립트가 10 BTC 이상의 유의미한 거래만 자동으로 필터링합니다.
   - 분석에 필요한 데이터만 정제하여 CSV 파일(`data/output/processed_transactions.csv`)로 저장합니다.
     ↓
3. RPC를 통한 심층 분석 (src/analysis.py)
   - 파이프라인이 처리된 CSV에서 트랜잭션 해시를 읽어옵니다.
   - JSON-RPC 통신을 통해 Bitcoin Core 노드에 각 트랜잭션의 상세 정보(입력, 출력, 총액 등)를 조회합니다. 이 단계는 핵심적인 API 연동 부분입니다.
     ↓
4. 결과 생성 (Output Generation)
   - 최종적으로 분석된 거래 총액, 수신 주소 등의 결과를 출력하여 명확하고 실행 가능한 정보를 제공합니다.
```

이 워크플로우는 원본 데이터를 가치 있는 정보로 변환하는 자동화된 프로세스를 구축하는 역량을 보여줍니다.

## 6. 설치 및 실행 방법

### 6.1. 환경 설정
```bash
# 1. 프로젝트 클론
git clone <repository_url>
cd bitcoin_project

# 2. 필요 라이브러리 설치
pip install -r requirements.txt
```

### 6.2. 실행 순서
```bash
# (선택) data/ 폴더에 분석할 .tsv 데이터 준비 (샘플 데이터 포함됨)

# 1. 데이터 전처리 파이프라인 실행
python -m src.main

# 2. 분석 스크립트 실행
python -m src.analysis
```
참고: 시뮬레이션 모드
`src/config.py`의 `SIMULATION_MODE`가 기본값(`True`)으로 설정되어 있어, 실제 Bitcoin 노드 없이도 샘플 데이터를 통해 분석을 실행할 수 있습니다. 실제 노드에 연결하려면 이 값을 `False`로 변경하고 RPC 설정을 업데이트해야 합니다.

## 7. 프로젝트 성과 및 향후 계획

### 7.1. 주요 성과
- 문제 해결 능력: 암호화폐 시장의 정보 비대칭성 문제를 기술적으로 해결할 수 있음을 성공적으로 증명했습니다.
- 기술적 구현 능력: 데이터 수집, 처리, 외부 API(RPC) 호출을 수행하는 기능적 데이터 파이프라인을 Python으로 구축했습니다.
- 실용적 인사이트: 거대 규모 트랜잭션을 효과적으로 식별하고 분석하여, 정교한 시장 분석 도구의 기반을 마련했습니다.

### 7.2. 향후 계획 (v2.0)
현재의 결과물은 강력한 PoC(Proof-of-Concept)입니다. 다음 단계는 이 시스템을 채용 공고에서 언급된 'Agent' 개념과 유사한, 보다 동적이고 지능적인 시스템으로 발전시키는 것입니다.

- 실시간 데이터 수집: 수동 데이터 다운로드 방식을 Blockchair API 연동을 통해 실시간 스트리밍 방식으로 전환합니다.
- '모니터링 에이전트'로의 발전: 시스템이 지속적으로 실행되면서 실시간으로 블록체인을 모니터링하고, 특정 고래의 행동(예: 거래소 지갑으로의 대규모 이동)에 따라 알림을 생성하는 자율적인 '에이전트'로 고도화합니다.
- 고급 분석 및 Vector DB 도입: 더 복잡한 분석 모델을 구현하고, Vector DB를 활용하여 트랜잭션 패턴이나 고래 프로필 간의 유사성을 찾는 기능을 탐색합니다.
